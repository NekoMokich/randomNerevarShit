# Server Hub — Win9x-панель для домашнего сервера

Самодостаточная веб-панель в стиле Windows 9x плюс небольшой Python-сервер,
который раздаёт саму панель и отдаёт метрики системы (CPU / RAM / Load / Disk).

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | панель: HTML + CSS + JS (без настроек — они в `config.js`) |
| `config.js` | **все настройки** панели: имя сервера, адреса, сервисы, System Monitor (включая скрываемые точки монтирования), аудио-плеер, скины, тема оформления, запоминание раскладки, Help |
| `server.py` | сервер: раздаёт панель, метрики, картинки, музыку, скины и раскладку |
| `pics/` | содержимое Picture Viewer: картинки **и** ascii-арт (`.txt`) — отдаётся по `/pics/<имя>` |
| `music/` | треки аудио-плеера — отдаются по `/music/<имя>`, список `/api/music`; **сами файлы в git не кладутся** |
| `skins/` | скины плеера `.wsz` / `.zip` (Winamp 2 / Qmmp) — `/skins/<имя>`, список `/api/skins`; **сами файлы в git не кладутся** |
| `layout.json` | сохранённая раскладка панели (`/api/layout`) — создаётся при первом сохранении, в `.gitignore` |
| `nerevar-hub.service` | unit для systemd — автозапуск при загрузке |

Зависимостей нет: нужен только Python 3.6+ (стандартная библиотека) и браузер.

При запуске рядом со скриптом дополнительно создаётся `server.pid`
(номер процесса) — он в `.gitignore` и в репозиторий не попадает.

### Что не попадает в git

Личное и тяжёлое остаётся локально — всё перечислено в `.gitignore`:

| файл | почему |
|---|---|
| `music/*` | свои треки: в git идёт только `music/README.md` |
| `skins/*` | скины Winamp/Qmmp: в git идёт только `skins/README.md` |
| `layout.json`, `layout.json.tmp` | раскладка окон — личные данные |
| `server.pid` | создаётся при запуске сервера |
| `__pycache__/`, `*.pyc`, `.DS_Store`, `Thumbs.db` | служебные файлы |

После клонирования панель работает сразу: HTML, сервер, арт из `pics/` и
документация на месте; треки и скины добавляются отдельно — инструкции в
`music/README.md` и `skins/README.md`.

## Быстрый старт (проверка вручную)

```bash
cd nerevar-hub
python3 server.py --port 80
```

Открой `http://<ip-сервера>/` — панель и метрики подняты на одном порту,
поэтому CORS настраивать не нужно.

Флаги:

```
--port 80           порт (по умолчанию 80)
--host 0.0.0.0      адрес привязки (по умолчанию все интерфейсы)
--cors              добавить Access-Control-Allow-Origin: *
                    (нужно, только если открывать index.html с диска,
                     а сервер дергать по HTTP с другого порта)
--music-dir PATH    папка с треками плеера (по умолчанию music/
                    рядом со скриптом); скины же всегда берутся
                    из папки skins/ рядом со скриптом
--cpu-interval 1.0  период замера CPU в секундах
--pidfile PATH      куда записать PID (по умолчанию server.pid рядом
                    со скриптом); пустая строка или --no-pidfile —
                    не создавать
```

## Лог и остановка процесса

Каждая строка лога помечена именем файла и PID процесса, которому
принадлежит:

```
[server.py pid=149047] Nerevar Hub запущен: http://0.0.0.0:8077
  страница  : /
  настройки : /config.js -> /opt/nerevar-hub/config.js
  метрики   : /api/stats
  index     : /opt/nerevar-hub/index.html
  остановить: kill 149047
             kill $(cat /opt/nerevar-hub/server.pid)

[server.py pid=149047] 127.0.0.1 - "GET /api/stats HTTP/1.1" 200 -
[server.py pid=149047] получен сигнал 15 — останавливаемся
[server.py pid=149047] остановлено
```

При старте рядом со скриптом создаётся `server.pid` с номером процесса,
при штатной остановке файл удаляется (если в нём лежит PID **этого**
запуска — чужой, более новый экземпляр не трогается).

Три способа остановить:

```bash
kill 149047                       # PID берёшь из лога
kill $(cat server.pid)            # PID берёшь из файла
systemctl stop nerevar-hub         # если работает через systemd
```

`journalctl -u nerevar-hub -f` — там те же строки с `[server.py pid=…]`.

Найти живой процесс и его PID:

```bash
pgrep -af 'server\.py'            # покажет PID и полную командную строку
```

Запуск от непривилегированного пользователя на порт 80 без root:

```bash
sudo setcap 'cap_net_bind_service=+ep' "$(readlink -f /usr/bin/python3)"
python3 server.py --port 80
```

## Запуск через systemd (автозапуск)

```bash
# 1. Кладём файлы
sudo mkdir -p /opt/nerevar-hub
sudo cp index.html config.js server.py /opt/nerevar-hub/

# 2. Ставим unit
sudo cp nerevar-hub.service /etc/systemd/system/

# 3. Включаем
sudo systemctl daemon-reload
sudo systemctl enable --now nerevar-hub

# 4. Проверяем
systemctl status nerevar-hub
curl http://localhost/api/stats
journalctl -u nerevar-hub -f      # логи
```

Если папка лежит не в `/opt/nerevar-hub` — поправь `WorkingDirectory`
и `ExecStart` внутри `nerevar-hub.service`.

По умолчанию сервис запущен от root (иначе нельзя занять порт 80).
В файле unit раскомментирован запасной вариант **без root** —
через `AmbientCapabilities=CAP_NET_BIND_SERVICE`.

## API метрик

`GET /api/stats` отдаёт JSON:

```json
{
  "cpu": 7.5,
  "load1": 1.3,
  "cores": 16,
  "mem_used": 27.1,
  "mem_total_gb": 31.3,
  "disk_used": 79.7,
  "disk_total_gb": 457.1,
  "disks": [
    {"mount": "/", "device": "nvme0n1p2", "device_full": "/dev/nvme0n1p2",
     "fstype": "ext4", "used": 79.7, "total_gb": 457.1, "free_gb": 92.8},
    {"mount": "/mnt/data", "device": "sdb1", "device_full": "/dev/sdb1",
     "fstype": "ext4", "used": 41.2, "total_gb": 438.1, "free_gb": 257.6}
  ],
  "raid": [
    {"name": "md0", "level": "raid1", "state": "clean",
     "online": 2, "total": 2, "status": "UU", "size_gb": 1862.9,
     "progress": null,
     "components": [
       {"device": "sdb1", "flag": "ok", "size_gb": 446.1},
       {"device": "sda1", "flag": "ok", "size_gb": 465.8}
     ]}
  ],
  "uptime": "3h 39m",
  "ts": 1793643510
}
```

| Поле | Источник |
|---|---|
| `cpu` | разница тиков `cpu` из `/proc/stat` (фоновый поток, раз в секунду) |
| `load1`, `cores` | `os.getloadavg()`, `os.cpu_count()` |
| `mem_used`, `mem_total_gb` | `/proc/meminfo`: `MemTotal`, `MemAvailable` |
| `disk_used`, `disk_total_gb` | `os.statvfs('/')` (сводный по корню) |
| `disks[]` | `/proc/mounts` + `os.statvfs()` по каждой точке монтирования |
| `raid[]` | `/proc/mdstat`, размеры компонентов — `/sys/class/block/*/size` |
| `uptime` | `/proc/uptime` |

`cpu` может быть `null` в первые секунды после старта — панель в этом
случае показывает прочерк и продолжает опрашивать.

Все маршруты `server.py` (поддерживаются `GET` и `HEAD`):

| Путь | Отдаёт |
|---|---|
| `/` | `index.html` — панель |
| `/config.js` | настройки панели (объект `CONFIG`), без кэша |
| `/api/stats` | JSON с метриками выше |
| `/api/pics` | JSON со списком файлов в `pics/` (картинки и арт) |
| `/pics/<имя>` | картинку или ascii-арт из папки `pics/` |
| `/api/music` | JSON `{"tracks":[...]}` — аудиофайлы из папки `music/` |
| `/music/<имя>` | трек из папки `music/`, с поддержкой `Range` (перемотка) |
| `/api/skins` | JSON `{"skins":[...]}` — файлы `.wsz`/`.zip` из `skins/` |
| `/skins/<имя>` | файл скина (zip-архив) |
| `/api/fonts` | JSON `{"families":[...],"source":"fontconfig"\|"scan"}` — шрифты, установленные в системе (см. «Шрифты») |
| `/api/layout` | раскладка панели: `GET`/`HEAD` — прочитать, `POST` — сохранить, `DELETE` — стереть (см. «Конструктор раскладки») |
| `/favicon.ico` | 204, пустое тело |
| всё остальное | 404 |

Маршруту `/api/layout` также отвечает `OPTIONS` (нужно, если панель
раздаётся с другого origin и включён `--cors`).

`/api/pics` отдаёт `{"images":[...],"art":[...]}` — имена файлов верхнего
уровня в `pics/`; панель берёт оттуда имя для случайного выбора.

Файлы из `pics/` отдаются только с расширением из списка (`.png`, `.jpg`,
`.gif`, `.webp`, `.svg`, … и `.txt` для ascii-арта), только внутри самой
папки и только как есть — никакой обработки. Подробности и заголовки —
в разделе «Картинки и GIF».

## Настройка панели

Все настройки — в отдельном файле **`config.js`** рядом с `index.html`
(объект `window.CONFIG`). Сам панельный HTML править не нужно:
изменил `config.js` — обновил страницу (F5), сервер отдаёт его без
кэша. Подробное описание всех полей — в шапке `config.js`.

Окно **System Monitor** управляется блоком:

```js
monitor:{
  enabled:true,           // false — окна и кнопки в таскбаре не будет
  windowTitle:'System Monitor',
  icon:'M',
  endpoint:'/api/stats',  // можно 'http://192.168.x.x/api/stats'
  interval:2000,          // период опроса, мс
  timeout:2500,           // таймаут запроса, мс
  width:360,              // желаемый размер окна
  height:225,             // (оно само подыщет себе свободное место)
  exclude:['/boot']       // какие точки монтирования не показывать
}
```

Если сервер недоступен, окно показывает `N/A — host unreachable`,
полоски становятся серыми, ошибок JS в консоли нет.

Окно **Terminal** настраивается блоком `CONFIG.term`: `enabled`,
`windowTitle`, `icon`, `startOpen`, `width`, `height`, `user`,
`startup`, `logo`. Что печатает консоль при запуске — массив `startup`:
обычная строка печатается как есть, строка с префиксом `$ `
показывается как приглашение с командой и выполняется. Подробнее —
раздел «Терминал» ниже.

### Picture Viewer: арт и картинки

В `index.html` больше нет ни арта, ни списка картинок — только имена
файлов, и лежат они в `config.js`:

```js
artFile:'ASCII_ART.TXT', // ascii-арт: файл в папке pics/ ('' — не грузить)
picFile:'',              // что показать при загрузке: 'cat.png'
                         // или '~.png' / '~.gif' / '~' — случайная
viewers:2,               // сколько окон Picture Viewer (1..6)
```

* `artFile` — имя (или путь внутри `pics/`); файл читается по
  `/pics/<имя>` при каждой загрузке страницы. Чтобы поменять арт,
  достаточно положить свой `.txt` в `pics/` и указать его имя в
  `config.js` — сам `index.html` не трогаем. Файла нет — в заголовке окна
  `Cannot open: …`, остальная панель работает.
* `picFile` — какая картинка откроется сразу. Пусто — окно остаётся
  на ascii-арте.
* `picFile:'~.png'` (или `~.gif`, или просто `~`) — **каждую загрузку
  случайная** картинка нужного расширения из `pics/`: панель запрашивает
  `/api/pics` и выбирает имя из вернувшегося списка. Список свежий на
  каждую загрузку, так что новая картинка в `pics/` начинает выпадать
  сразу после обновления вкладки.
* `viewers` — сколько окон Picture Viewer открывать (1–6, по умолчанию 2).
  Окна **не зависят друг от друга**: у каждого своё фото, свой зум
  (`View → Zoom`), свой режим «арт/картинка» и своё имя в заголовке —
  `Picture Viewer`, `Picture Viewer 2`, … Содержимое у всех общее
  (`artFile`/`picFile` из одного `config.js`), поэтому при `picFile:'~'`
  **каждое окно выбирает свою** случайную картинку: число случайности
  тянется по одному разу на окно. Фото в нужное окно отправляет
  `File → Open image…` — диалог идёт в последнее активное окно и подпись
  `Opens in …` говорит, куда картинка попадёт; файл можно и просто
  перетащить на любое из окон. Закрытое окно открывается обратно из
  таскбара, и оно же исчезает из раскладки до следующего открытия.

### Диски и RAID

Окно состоит из трёх блоков: обычные метрики (CPU / RAM / Load),
раздел **Storage** и раздел **RAID**.

* **Storage** — по строке на каждый смонтированный том (кроме
  попутных: `CONFIG.monitor.exclude` по умолчанию прячет `/boot` и
  `/boot/efi`; корень `/` показывается всегда): точка
  монтирования, устройство, полоска занятости и подпись вида
  `92.8 GB free of 457 GB · ext4`. Счётчик раздела — `6 disks`.
  Полоска становится оранжевой с 75% и красной с 90%.
* **RAID** — по строке на каждый массив из `/proc/mdstat`: уровень,
  размер, состояние и физические диски внутри массива
  (`●` рабочий, `○` запасной, `×` вышел из строя). Полоска показывает
  идущее восстановление (`recovery 42%`), а если его нет — долю
  рабочих дисков; `DEGRADED` и `inactive` выводятся красным.
  Счётчик раздела — `3 arrays`.
* Оба раздела появляются только когда есть данные: mdraid не
  используется — блок RAID не отображается вообще, старый сервер без
  поля `disks` откатывается на единственный корневой том.
* Если томов много и окно не влезает по высоте, внутри появляется
  полоса прокрутки.

## Раскладка окон

* **Server** — всегда сверху слева, ширина по содержимому.
* **System Monitor** — сам подбирает свободное место рядом с этими двумя
  окнами (сверху справа, под серверным окном и т.д.). Если места нет
  (узкий экран) — встаёт там, где меньше всего перекрытий.
* **Picture Viewer** — снизу справа, размер по пропорциям ASCII-арта.
  Окон может быть несколько (`CONFIG.viewers`): они делят свободную колонку
  на доли — в широком окне встают в ряд по низу, на узком экране — друг под
  другом. Закрытые окна места не занимают, а перетащенные руками своё место
  держат до Reset. При этом авто-окна объезжают перетащенные: если их доля
  попадает на чужое ручное окно, оно уезжает на ближайшее свободное место,
  а если свободного места нет вовсе (узкий экран, окно Server во всю высоту)
  — просмотрщики перераскладываются заново и ужимаются под экран, только бы
  не налезать друг на друга. Намеренную «стопку» окон из раскладки такое
  вмешательство не трогает.

Любое окно тянется за заголовок и меняет размер за уголком справа снизу.
После ручного перетаскивания System Monitor **запоминает** своё место
до перезагрузки страницы.

ASCII-арт в `<pre>` менять не нужно: он сам подгоняется под размер окна
без искажений, масштаб — меню **View → Zoom**.

### Конструктор раскладки (View → Layout constructor…)

Панель запоминает, как вы её разложили, и открывается одинаково на всех
устройствах — раскладка лежит **на сервере** (`layout.json` рядом с
`server.py`), а не в браузере.

Открывается **View → Layout constructor…** — всплывает палитра:

* **Windows** — какие окна открыты (галочка = открыто);
* **Available services** — какие карточки сервисов показывать;
  выключенные не отрисовываются и не считаются в статусбаре;
* **Save layout** — сохранить на сервер (`POST /api/layout`);
* **Reset layout** — вернуть расстановку по умолчанию
  (`DELETE /api/layout` + стирание локального зеркала).

Сохраняется всё: открытые/закрытые окна, их положение и размер, порядок
(что сверху), выключенные карточки сервисов. Положение и размер хранятся
**долями от размера рабочего стола**, поэтому на другом разрешении окно
встаёт на то же место и никогда не вылезает за рабочий стол (и за таскбар
они не выходят: таскбар — вне сцены). Окно, развернутое на весь экран,
запоминает свои размеры до разворачивания.

Изменения (перетащил, изменил размер, открыл/закрыл окно, снял галочку
сервиса) сохраняются автоматически с задержкой ~0.4 с; **View → Save
window layout** — немедленно. Если сервер недоступен, раскладка
временно лежит в `localStorage` и примется при следующей загрузке.

Отключить полностью — `rememberLayout:false` в `config.js`: панель всегда
будет открываться так, как задумано по умолчанию. Файл `layout.json`
попадает в `.gitignore`.

## Тёмная тема

Две темы оформления: классическая светлая и тёмная — так панель выглядит
при включённом Dark Reader: бирюзовый рабочий стол, почти чёрные тела
окон, тёмно-синие заголовки, светло-голубые подписи, белый текст,
синие и оранжевые шкалы.

**Из `config.js`** — поле `theme`:

```js
theme:'dark',   // 'dark' | 'light'
```

**Кнопкой в панели** — **View → Dark theme** (в меню View, галочка
показывает текущую тему). Кнопка запоминает выбор в браузере и кладёт
его в раскладку на сервере, поэтому тема одинакова на всех устройствах.
Выбор кнопки **важнее** `CONFIG.theme`: чтобы вернуть то, что задано в
`config.js`, нажмите **View → Reset window layout** — он забудет выбор.

Порядок при загрузке: сохранённый выбор (браузер) → `CONFIG.theme` →
светлая. Тема применяется до первой отрисовки (в `<head>`), поэтому
рабочий стол не мигает белым.

Устройство темы: в `index.html` все цвета вынесены в переменные
(`:root` — светлая тема, `html[data-theme=dark]` — только переопределение
переменных). Светлая тема от этого не меняется, а тёмная описывается
одним блоком в конце `<style>`.

## Шрифты

Весь интерфейс панели набран одним шрифтом — он задаётся двумя способами.

**Из `config.js`** — поле `font`, строка `font-family`, ровно как в CSS:

```js
font:'Tahoma, Verdana, sans-serif',        // '' — шрифт по умолчанию
font:'DejaVu Sans',                        // шрифт, стоящий в системе
font:'Noto Sans, DejaVu Sans, sans-serif', // список через запятую
```

**Выбором в панели** — **View → Font…**: окно перечисляет все шрифты,
которые реально установлены на машине, и рисует каждое имя **его собственным
начертанием** — видно, как шрифт выглядит до того, как выберешь. Строка
поиска фильтрует список; если нужного шрифта в списке нет, впишите имя в
эту же строку и нажмите **Enter** — панель применит его как есть. Кнопка
**Use default** возвращает то, что задано в `config.js`.

Выбор запоминается в браузере и едет в раскладку на сервере — так же,
как тема, и тоже **важнее** `CONFIG.font`. **View → Reset window layout**
забывает выбор и возвращает шрифт из `config.js`.

Порядок при загрузке: сначала в `<head>` применяется сохранённый выбор
браузера, затем `CONFIG.font` (поэтому панель не мигает чужим шрифтом),
а когда раскладка приехала с сервера — её шрифт, если он там есть.
Фактический приоритет: **раскладка на сервере → выбор в браузере →
`CONFIG.font` → шрифт по умолчанию**.

Откуда берётся список — `GET /api/fonts`, `{"families":[...],"source":...}`:

* сначала `server.py` спрашивает **fontconfig** — `fc-list --format='%{family}\n'`.
  В Linux системные шрифты как раз так и устроены: fontconfig видит и
  `/usr/share/fonts`, и пользовательские папки, и свои настройки; на этой
  машине, например, 818 семейств;
* если утилиты нет (минимальный дистрибутив, контейнер, NAS, Windows) —
  сервер сам обходит `/usr/share/fonts`, `/usr/local/share/fonts`,
  `~/.local/share/fonts`, `~/.fonts` и читает имя семейства прямо из
  таблицы `name` файла TTF/OTF/TTC. Библиотеки не нужны: формат открытый
  и стабильный с девяностых, файл целиком в память не читается;
* `source` — какой путь сработал: `fontconfig` или `scan`. Результат
  кэшируется на 5 минут: шрифты меняются редко, а страница не должна ждать.

Арт-окно и окно плеера набраны моноширинными шрифтами — поле `font` их
не трогает, раскладка ASCII-арта от настройки не зависит.

## Часы и календарь

На часах в таскбаре **две строки**: сверху время, под ним дата.

```
   11:45 PM
Mo/Nov/2/2026
```

Формат даты — `День недели в 2 символа / Мес / Д / Г`, всегда
по-английски (`Mo`, `Nov`). Время и дата видны **на любой ширине**:
рамка часов подчиняется дате (она шире), поэтому отдельного правила
«спрятать время на узком экране» больше нет — раньше время до 700px
пряталось, теперь нет. Меняются только кнопки сервисов:

| ширина | часы | кнопки сервисов |
|---|---|---|
| > 500px | время + дата | подписи |
| ≤ 500px | время + дата | подписи, ужимаются |
| ≤ 420px | время + дата | иконки без подписей |

Клик по **часам** открывает календарь:

* переключение месяцев кнопками ◄ / ►;
* сегодняшний день обведён пунктиром, выбранный — залит синим;
* кнопка **Today** возвращает к текущему месяцу и выбирает сегодня;
* клик по дате чужого месяца переключает на этот месяц;
* при открытии всегда показывается текущий месяц, открытое состояние
  подсвечено на самих часах.

Закрывается повторным кликом по часам, кликом в любую другую точку
экрана или **Esc**. Текст календаря английский — как весь интерфейс.
Отдельных настроек у него нет, разметка и стили — блок `.calpop` в
`index.html`.

## Картинки и GIF

Окно **Picture Viewer** показывает не только ASCII-арт, но и обычные
картинки и анимированные GIF (анимацию проигрывает браузер сам — ничего
настраивать не нужно).

**ASCII-арт тоже лежит в `pics/`**, а не в `index.html`: имя файла
хранится в `config.js` (`CONFIG.artFile`, по умолчанию `ASCII_ART.TXT`)
и читается по `/pics/ASCII_ART.TXT` при каждой загрузке. Свой
арт — положи `.txt` в `pics/` и укажи имя в `CONFIG.artFile`, сам
`index.html` не трогай. Подробнее — в разделе
[«Picture Viewer: арт и картинки»](#picture-viewer-арт-и-картинки).

**Как открыть:**

* **File → Open image…** — вписать адрес (URL) и нажать **Open**, либо
  нажать **Browse…** и выбрать файл на диске;
* просто **перетащить файл на окно** Picture Viewer — пока файл висит над
  окном, вокруг него пунктирная рамка (перетаскивание работает и с
  не-картинками: в заголовке появится `Not an image: …`, содержимое не
  меняется).

**Что поддерживается:** PNG, JPG, WEBP, SVG, GIF и вообще всё, что
понимает браузер. GIF анимируется без дополнительных действий.

**Поведение:**

* картинка вписывается в окно целиком (contain) — пропорции никогда не
  искажаются;
* окно Picture Viewer подстраивается под пропорции картинки (если вы не
  меняли его размер руками);
* **View → Zoom** (кнопки `+` / `−` / сброс) действует и на картинку;
* в заголовке окна — имя файла;
* **File → Back to ASCII art** возвращает исходный ASCII-арт.

Если адрес не открывается, текущая картинка **не ломается**: в заголовке
появится `Cannot open: …`, а диалог останется открытым — можно исправить
адрес и нажать **Open** снова. **Esc** закрывает диалог.

Картинку можно взять откуда угодно:

* **файл с вашего диска** — `Browse…` или перетаскивание на окно;
* **картинка с самого сервера** — положи её в папку `pics/` рядом с
  `index.html` и открой по адресу `/pics/имя-файла.gif` (в диалоге можно
  писать и полный адрес: `http://192.168.1.10/pics/имя.gif`);
* **любой другой URL** — например, картинка, которую уже отдаёт какой-то
  ваш сервис.

Списка файлов **в диалоге** нет — имя нужно знать заранее. Сам сервер
при этом содержимое отдавать умеет (`GET /api/pics`), им пользуется
случайный выбор (см. ниже).

### Что показывать при загрузке: `CONFIG.picFile`

```js
picFile:'',          // по умолчанию — пусто, окно остаётся на ascii-арте
```

| значение | что откроется |
|---|---|
| `'cat.png'` | конкретная картинка из `pics/` |
| `'~.png'` | **случайная** `.png` из `pics/` |
| `'~.gif'` | случайная анимированная |
| `'~'` | любая картинка из `pics/` |
| `''` | ничего — ascii-арт |

Работает так: панель запрашивает `/api/pics`, получает список имён,
отбирает подходящие по расширению и берёт одно наугад. Выбор
делается **при каждой загрузке страницы** — положил новую картинку
в `pics/`, обновил вкладку, и она уже может выпасть.

Если под `~.png` в `pics/` ничего нет, в заголовке окна появится
`Cannot open: ~.png`, а остальная панель продолжит работать.

### Раздача картинок из `pics/`

`GET /pics/<имя>` отдаёт файл из папки `pics/` (она может не
существовать — тогда 404):

* отдаются только расширения-картинки: `.png` `.jpg` `.jpeg` `.gif`
  `.webp` `.apng` `.avif` `.bmp` `.ico` `.svg`; всё остальное — 404;
* путь нормализуется через `realpath` и сверяется с адресом папки —
  `../`, абсолютный путь и симлинки наружу дают 404;
* каталоги, пустые и несуществующие имена — 404, списка содержимого нет;
* заголовки: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`,
  а для типов, в которых возможны скрипты (`svg`), дополнительно
  `Content-Security-Policy: default-src 'none'`;
* тело читается кусками по 64 КБ — большие GIF не оседают в памяти.

Папка с картинками не обязательна: без неё панель работает как раньше.

Разметка картинки — `<img class="art-img">` рядом с `<pre>` внутри
`.art-wrap`, логика — блок «Picture Viewer: картинки и GIF» в
`index.html`.

## Аудио-плеер

Окно **Audio Player** (меню **File → Audio player**) проигрывает музыку
с сервера: список треков панель берёт из `GET /api/music`, сами файлы —
по `GET /music/<имя>` (перемотка работает через `Range`).

```js
music:{
  enabled:true,           // false — окна и кнопки в таскбаре не будет
  base:'music/',          // URL-префикс папки с треками
  list:'api/music',       // endpoint со списком ('' — не спрашивать)
  tracks:[],              // ручной список вместо endpoint
  startOpen:false,        // открывать окно при загрузке страницы
  volume:0.8,             // 0..1
  loop:'all',             // 'off' | 'all' | 'one' (кнопка R)
  shuffle:false           // перемешивание (кнопка S)
}
```

Музыка по умолчанию лежит в `music/` рядом со скриптом. Свою папку
(например, смонтированный диск) подключают флагом сервера:

```bash
python3 server.py --music-dir /mnt/hdd/music
```

`base` может быть и внешним адресом целиком — тогда `list` можно
обнулить, а треки перечислить вручную в `tracks`.

Управление: play/pause, stop, prev/next, ползунок позиции, громкость,
**S** — shuffle, **R** — repeat, клик по треку в списке — играть его.

Если трек не играет и в статусе показано
`Cannot play: … — unsupported or damaged audio file`, браузер не смог
декодировать файл. Известный случай: FLAC с битой обложкой (пустой MIME
в блоке PICTURE) Chromium отвергает, хотя аудио в целом исправен —
чинится одной командой:

```bash
metaflac --remove --block-type=PICTURE трек.flac
```

## Скины плеера (Qmmp / Winamp 2)

Плеер умеет выглядеть как настоящее окно Winamp 2 / Qmmp: рисуется на
`<canvas>` по координатам оригинала — титул, кнопки транспорта,
ползунки, плейлист с цветами из `pledit.txt` скина.

**Формат:** `.wsz` (или `.zip`) с BMP-файлами внутри: `main.bmp`,
`cbuttons.bmp`, `titlebar.bmp`, `numbers.bmp`, `pledit.bmp`,
`pledit.txt` и др. Готовые скины лежат, например, на
<https://qmmp.ylsoftware.com/files/skins/winamp-skins/>.

**Как подключить:**

* положи файл в папку `skins/` — он появится в выпадающем списке над
  окном Winamp;
* либо нажми **Skin…** и выбери `.wsz` у себя на диске — файл никуда
  не отправляется, архив и BMP разбирает сам браузер;
* либо перетащи `.wsz` прямо на окно плеера.

**Настройки** (`CONFIG.music.skins`):

| Поле | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `true` | `false` — панель выбора скина не показывается |
| `dir` | `'skins/'` | URL-префикс папки со скинами (её отдаёт сервер) |
| `list` | `'api/skins'` | endpoint со списком; `''` — список не нужен |
| `start` | `''` | скин, включаемый при загрузке страницы |
| `scale` | `2` | во сколько раз увеличено окно Winamp |
| `playlistHeight` | `196` | высота плейлиста в пикселях скина |

**Что работает:** кнопки транспорта (с анимацией нажатия), ползунки
громкости/баланса/перемотки кликом, кнопки EQ и плейлиста, перетаскивание
окна за титул скина, строки плейлиста (клик — играть, колесо —
прокрутка), повтор/перемешивание, включение/выключение плейлиста.
Возврат к обычному виду — пункт **No skin (classic)** в том же списке.

Разбор ZIP (`DecompressionStream`) и BMP происходит целиком в браузере,
сервер просто отдаёт файлы; нужен современный браузер (Chrome/Edge/
Firefox недавних версий). Подробнее — в `skins/README.md`.

## Терминал (окно-пародия на консоль)

Окно **Terminal** выглядит как старая консоль: чёрный экран, моноширинный
шрифт, приглашение `user@server:~$`. В обеих темах панели консоль
остаётся чёрной — как настоящий терминал. Открывается **File →
Terminal** или кнопкой в таскбаре, закрывается крестиком или командой
`exit`.

**Главная команда — `fetch`** (синоним `neofetch`): сводка о машине в
стиле fastfetch — ASCII-логотип слева, поля справа:

* из `/api/stats`: `OS`, `Host`, `Kernel`, `Uptime`;
* со стороны браузера: `Theme`, `Font`, `Resolution`, `Panel`, `CPU`,
  `Memory`, `Disk (…)` — по строке на каждый диск, `Services` (сколько
  карточек включено), `Viewers`, `LAN`, `Tailscale`;
* если сервер недоступен — `fetch: N/A — host unreachable`.

**Команды** (полный список печатает `help`):

| Команда | Что делает |
|---|---|
| `fetch`, `neofetch` | сводка о системе (см. выше) |
| `help` | список команд |
| `clear`, `cls` | очистить экран |
| `date`, `uptime`, `whoami` | дата по-английски, аптайм, текущий пользователь |
| `uname [-a\|-r\|-s\|-m]` | система, ядро, архитектура — из `/api/stats` |
| `echo <текст>` | повторить текст |
| `ls` | что лежит в `pics/`, `music/`, `skins/` |
| `cowsay <текст>` | корова озвучит вашу фразу (по умолчанию — приветствие) |
| `fortune` | случайная поговорка из встроенных |
| `cal [месяц] [год]` | сетка месяца, как в `cal`, сегодняшний день зелёный |
| `df` | таблица места на дисках (Filesystem/Size/Used/Avail/Use%) |
| `free` | память сервера: total / used / free |
| `ps` | «процессы»: сервер, окна и карточки как `PID TTY STAT CMD` |
| `man <команда>` | страница справки; у команды нет страницы — `No manual entry for …` |
| `theme dark\|light` | переключить тему панели |
| `open <server\|viewer\|monitor\|music\|help\|term>` | открыть окно |
| `about` | что это за панель |
| `exit` | закрыть окно |
| `sudo <команда>` | «nice try» |

Стрелки ↑/↓ — история команд, **Tab** — дополнение имени команды,
**Ctrl+L** — очистить (как `clear`), клик по выводу переносит курсор
во строку ввода, если ничего не выделено. Вывод хранит последние 800
строк.

**Стартовый вывод** — `CONFIG.term.startup`, массив строк: обычная
строка печатается как есть, строка с префиксом `$ ` показывается как
приглашение с командой и выполняется. По умолчанию консоль здоровается
и сразу печатает `fetch`; пустой массив (`startup:[]`) даёт чистое
приглашение.

**Настройки** (`CONFIG.term`):

| Поле | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `true` | `false` — убрать окно, кнопку таскбара и пункт меню |
| `windowTitle` | `'Terminal'` | заголовок окна |
| `icon` | `'>'` | значок в заголовке и на кнопке таскбара |
| `startOpen` | `true` | открывать окно при загрузке страницы |
| `width` / `height` | `560` / `340` | желаемый размер; окно само ищет свободное место |
| `user` | `'nerevar'` | имя в приглашении и в первой строке `fetch` |
| `startup` | приветствие + `$ fetch` | что печатать при запуске |
| `logo` | `[]` | свои строки логотипа для `fetch`; пусто — встроенный |

Окно участвует в раскладке как обычное: объезжает другие окна (в том
числе подросший System Monitor), перетащенное за заголовок остаётся на
своём месте, а положение хранится в `layout.json` вместе со всеми
окнами — **View → Layout constructor…** показывает его в списке окон,
**Reset** возвращает авторасстановку.

## Безопасность

* Панель отдаёт метрики **без авторизации**. Держи порт 80 в локальной
  сети / Tailscale, наружу не пробрасывай.
* Нужен доступ к интернету — поставь перед `server.py` nginx/caddy
  с TLS и basic-auth.
* `server.py` отдаёт только свои пути: `/`, `/config.js`, `/api/stats`,
  `/api/pics`, `/api/music`, `/api/skins`, `/api/fonts`, `/api/layout`,
  картинки из
  `pics/`, треки из `music/`, скины из `skins/` (плюс 204 на
  `/favicon.ico`). Другие запросы — 404, произвольного чтения
  файловой системы по запросам нет. `/api/fonts` отдаёт только имена
  семейств шрифтов — ни путей, ни содержимого файлов.
* `POST /api/layout` пишет **один** файл — `layout.json` рядом с
  `server.py`: принимается только JSON-объект до 64 КБ, запись
  атомарная, никаких путей из запроса в файловую систему не уходит.
