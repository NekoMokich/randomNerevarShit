# Nerevar FM

Файловый менеджер для домашнего сервера: **веб-панель** для просмотра и
переноса файлов + **FTP** для выкачивания и загрузки с любого FTP-клиента.
Один процесс, один пароль, ноль зависимостей — только Python 3.6+ и браузер.

Оформление в духе домашних панелей Nerevar: файловый менеджер занимает
весь экран — без рабочего стола и таскбара; две панели как в старых
файловых менеджерах, скин **Windows 9x** и скин **WindowMaker / NeXTSTEP**
(переключается в меню View), тёмная тема поверх.

---

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | панель: разметка и **все стили** (блок `<style>`, обе темы и оба скина) |
| `app.js` | логика: окна, две панели, выделение, файловые операции, загрузка/скачивание, просмотрщик, закреплённые места |
| `config.js` | настройки панели (имя сервера, окна, стартовые папки, FTP-подпись) — **без секретов** |
| `config.json` | настройки сервера: пароль, порты, корень, логин FTP, стартовые места |
| `server.py` | HTTP-сервер (панель + `/api/*`) и встроенный FTP-сервер |
| `places.json` | закреплённые места, сохранённые из панели (создаётся при первом сохранении, в `.gitignore`) |
| `server.pid` | PID процесса (создаётся при запуске, в `.gitignore`) |
| `nerevar-fm.service` | unit для systemd — автозапуск |

Зависимостей нет: `server.py` — стандартная библиотека Python, FTP написан
в нём же (никаких `pyftpdlib`).

## Быстрый старт

```bash
cd nerevar-fm

# 1. пароль! либо в config.json, либо флагом --password
nano config.json          # "password": "мой-пароль"

# 2. запуск
python3 server.py                       # HTTP :8090, FTP :2121, корень /
# или
python3 server.py --port 80 --ftp-port 21
```

Открыть `http://<ip-сервера>:8090/`, ввести пароль.
Тот же пароль — для FTP (`ftp://nerevar@<ip>:2121/`).

Если пароль нигде не задан — сервер сгенерирует случайный и напечатает его
в лог **один раз**. Если пароль остался `changeme` — сервер громко
предупредит при старте (это значение лежит в git, его нужно менять).

Сервер создаёт рядом `server.pid`; при штатной остановке удаляет (чужой
PID не трогает).

## Настройки: `config.json` и флаги

`config.json` (рядом с `server.py`, либо `--config /path`):

```json
{
  "password": "changeme",
  "http_host": "0.0.0.0",
  "http_port": 8090,
  "ftp_enabled": true,
  "ftp_host": "0.0.0.0",
  "ftp_port": 2121,
  "ftp_user": "nerevar",
  "ftp_pasv_min": 0,
  "ftp_pasv_max": 0,
  "ftp_max_clients": 0,
  "root": "/",
  "read_only": false,
  "view_password": "",
  "session_ttl": 604800,
  "audit_max": 500,
  "places": [
    { "name": "Root", "path": "/",     "icon": "/" },
    { "name": "Home", "path": "/home", "icon": "H" },
    { "name": "Mnt",  "path": "/mnt",  "icon": "M" }
  ]
}
```

Приоритет: **флаги > config.json > встроенные значения**.

| Флаг | Что делает |
|---|---|
| `--host`, `--port` | адрес и порт панели (по умолчанию `0.0.0.0:8090`) |
| `--root PATH` | корень файлов **для панели и FTP одновременно** (по умолчанию `/`) |
| `--password STR` | пароль API и FTP |
| `--ftp-port N`, `--ftp-user STR` | порт и логин FTP (по умолчанию `2121`, `nerevar`) |
| `--no-ftp` | не поднимать FTP совсем |
| `--config PATH` | другой `config.json` |
| `--pidfile PATH`, `--no-pidfile` | куда писать PID |
| `--cors` | `Access-Control-Allow-Origin: *` (только если открываешь `index.html` с диска) |
| `--read-only` | запретить все изменяющие операции (только просмотр/скачивание) |
| `--session-ttl N` | время простоя токена в секундах (по умолчанию `604800`) |
| `--ftp-pasv-min N`, `--ftp-pasv-max N` | диапазон PASV-портов (`0/0` — как раньше, случайный порт) |
| `--ftp-max-clients N` | максимум одновременно FTP-подключений (`0` — без лимита) |

Поле `root` — это и «песочница»: панель и FTP не могут выйти за него
(`../` за корень → 403 в API и 550 в FTP, симлинки наружу тоже режутся).
При `root: "/"` виден весь сервер — так и задумано.

Порты: 80 и 21 требуют прав root. Если запускаешь от обычного
пользователя, оставь 8090/2121 или выдай capability:

```bash
sudo setcap 'cap_net_bind_service=+ep' "$(readlink -f /usr/bin/python3)"
python3 server.py --port 80 --ftp-port 21
```

Пароль **никогда** не отдаётся в API (ни в `/api/status`, никуда) —
только сверяется.

## Панель

После входа файловый менеджер занимает **весь экран**: рабочего стола и
таскбара нет, две панели — каждая со своим путём, закреплёнными местами и
списком файлов. Viewer, Help, Places и диалоги открываются поверх.

### Что умеет

* просмотр каталогов и **навигация мышью**: двойной клик по папке или
  один клик по её иконке — внутрь, `..` — наверх, двойной клик по файлу
  открывает его, кнопки `←`/`→`/`↑` — назад/вперёд/вверх, закреплённые
  места — кнопками над списком; история навигации хранится отдельно
  для каждой панели;
* **перенос и копирование** между панелями: выделил → `F6` / `F5`,
  или перетащил мышью (перетаскивание по умолчанию переносит,
  с `Ctrl` — копирует);
* создание папки/файла, переименование, удаление (рекурсивно) — всё это
  и перенос, копирование, загрузка и сохранение текста можно отменить
  кнопкой `Undo` или `Ctrl+Z` (снимки хранятся вне корня и не видны
  ни в панели, ни по FTP);
* **загрузка файлов** с компьютера — кнопка Upload, `Ctrl+U` или просто
  перетащить файлы на панель. Во время передачи в правом нижнем углу
  показывается индикатор с процентами и объёмом (`1.2 MB / 3.4 MB`),
  он же работает при скачивании;
* **скачивание** выделенного — `Ctrl+D` / `Alt+D`, файл приходит как attachment;
* просмотрщик `F3`: **картинки**, **видео** и **аудио** проигрываются прямо
  в окне (видео перематывается благодаря HTTP Range), текстовые файлы
  открываются в текстовом поле; можно держать **несколько окон просмотра
  одновременно** — `F3` или кнопка `View` открывает каждый выделенный файл
  в отдельном окне, повторный вызов того же файла просто поднимает его окно;
  меню `File`/`View` и панель кнопок есть **только в текстовом редакторе**:
  у картинок (включая GIF), видео, аудио и бинарных файлов их нет,
  а закрытие окна останавливает воспроизведение;
* **любые текстовые файлы**: тип определяется по содержимому (валидная UTF-8
  без нулевых байтов), а не по расширению — открываются `.txt`, `.jsonc`,
  `.json5`, `.toml`, `.env`, `.properties`, `.cnf`, `.hcl`, скрипты и конфиги
  с любым расширением. Настоящие бинарники показывают сообщение с советом
  скачать файл;
* **редактор текста**: `Edit` / `File → Edit text` → правка →
  `File → Save file` / `Ctrl+S`, файл пишется на сервер атомарно (через
  временный файл, с сохранением прав). `File → Save as…` создаёт копию под
  другим именем, `Open with browser…` открывает текст в новой вкладке,
  `View → Reload` / `Ctrl+R` перечитывает файл, `Word wrap` переключает
  перенос строк; меню работают во всех открытых окнах Viewer;
  несохранённые изменения защищены подтверждением при закрытии;
  файлы >2 МБ открываются только для чтения;
* сортировка по имени/размеру/дате, кнопка `Dotfiles` и `Ctrl+H` для показа
  файлов/папок, начинающихся с точки;
* **закреплённые места** (диски/папки) — кнопки над списком; список
  хранится на сервере (`places.json`) и одинаков на всех устройствах;
* **быстрый фильтр** в каждой панели и **рекурсивный поиск** по имени или
  по содержимому (`File → Search…`, `Ctrl+Shift+F`), с регулярками и
  ограничением числа результатов;
* **пакетные операции**: переименование по шаблону с `{n}`/`{name}`,
  копирование пути/имени, `Touch now` и `chmod` для выделенного;
* **архивы**: распаковка ZIP/TAR(.gz/.bz2/.xz), создание архива из
  выделенных файлов прямо на сервере и просмотр содержимого архива —
  всё стандартными `zipfile`/`tarfile`, с проверкой путей распаковки;
* **свойства и хэши**: `Properties`, `SHA-256`/`MD5`, сравнение двух файлов
  по хэшу;
* **редактор**: номера строк, подсветка синтаксиса, `Find/Replace`,
  `Go to line`, выбор кодировки и `LF/CRLF`, черновики в браузере;
* **очередь загрузок**: каждый файл отдельной строкой с паузой,
  продолжением и отменой; загрузка кусками (1 МБ) поддерживает докачку,
  drag-and-drop папок сохраняет вложенные пути;
* **корзина и история**: удаление в корзину с восстановлением,
  история `Undo/Redo` и повтор последней отмены (`Ctrl+Shift+Z` / `Ctrl+Y`);
* **режимы доступа**: `read_only` и необязательный `view_password` только
  для чтения, журнал аудита и настройки сессии в `config.json`.

## FTP

Тот же корень (`root`), тот же пароль. Логин — `ftp_user` (по умолчанию
`nerevar`); имя пользователя можно вводить любое, важен пароль.

```
Адрес:        <ip-сервера>
Порт:         2121
Пользователь: nerevar
Пароль:       как в панели
```

Клиенты:

```bash
# curl — скачать/залить
curl -u nerevar ftp://192.168.1.10:2121/var/log/syslog -o syslog
curl -u nerevar -T backup.tar.gz ftp://192.168.1.10:2121/backups/

# lftp — зеркало папки
lftp -u nerevar ftp://192.168.1.10:2121 -e 'mirror /mnt/data /backup; bye'
```

Работает и в Total Commander / Midnight Commander / Nautilus / Finder
(адрес вида `ftp://nerevar@192.168.1.10:2121/`).

Поддерживаемые команды: `USER PASS SYST FEAT OPTS PWD CWD CDUP TYPE PASV
EPSV PORT EPRT LIST NLST MLSD MLST RETR STOR APPE DELE MKD RMD RNFR RNTO SIZE
MDTM REST NOOP LOGOUT QUIT HELP STAT`.

* `REST` + `RETR/STOR` — докачка/возобновление;
* `PASV` открывается на том IP, по которому пришёл клиент;
* всё внутри `root`: `CWD ../../etc` → `550`;
* 5 неверных паролей на одном соединении — `421` и разрыв;
* `TYPE A` не перекодирует переводы строк (файлы идут байт в байт);
* `MLST` отдаёт MLSD-строку для одного объекта, `LOGOUT` сбрасывает логин
  без закрытия соединения;
* `ftp_pasv_min`/`ftp_pasv_max` задают фиксированный диапазон PASV-портов —
  его проще открыть в файрволе, чем случайные порты;
* `ftp_max_clients` ограничивает число одновременно подключённых клиентов;
* действия FTP попадают в общий журнал аудита (пароль в лог не пишется).

**FTP — открытый протокол**, пароль и содержимое идут без шифрования.
Используй локальную сеть или VPN (Tailscale/WireGuard); наружу FTP не
пробрасывай — для внешнего доступа лучше панель за nginx/caddy с HTTPS.

## HTTP API

Все `/api/*` (кроме `POST /api/login`) требуют токен: заголовок
`X-Auth-Token: <token>` или `?token=<token>`.

| Метод и путь | Что делает |
|---|---|
| `POST /api/login` | `{"password":"…"}` → `{"token":"…","ttl":604800}`; 5 неудач/5 мин с IP → 429 |
| `GET /api/status` | `{"root":"/","ftp":{…},"ok":true}` |
| `GET /api/list?path=/dir` | список: `path`, `name`, `parent`, `entries[]` (`name`, `path`, `dir`, `size`, `mtime`, `mode`, `hidden`), `free`, `total` |
| `POST /api/mkdir` | `{"path":"/a/b"}` |
| `POST /api/newfile` | `{"path":"/a/b.txt"}` |
| `POST /api/write` | `{"path":"/a/b.txt","text":"..."}` → `{"ok","path","size","mtime"}`; UTF-8 до 8 МБ, атомарная запись через tmp + `os.replace` с сохранением прав |
| `POST /api/rename` | `{"from":"/a/old","to":"/a/new"}` |
| `POST /api/delete` | `{"items":["/a","/b"]}` → `deleted`, `errors[]` |
| `POST /api/move` | `{"items":[…],"dest":"/dir"}` → `moved`, `errors[]` |
| `POST /api/copy` | то же → `copied`, `errors[]` |
| `POST /api/undo` | `{}` → `{"ok","label","errors"}`; отменяет последнюю файловую операцию |
| `GET/POST/DELETE /api/places` | закреплённые места (`places.json`); POST — `{"places":[…]}`, max 64 |
| `POST /api/upload?path=/dir` | `multipart/form-data`, поля `file` (можно несколько) **или** сырое тело + `&name=имя`; пишет через `.part` → `os.replace` |
| `GET /api/download?path=/file` | только обычный файл, `Content-Disposition: attachment`, поддержка `Range` (206); папка/устройство → 400 `{"error":...}` |
| `GET /api/inline?path=/file` | для просмотра: картинки, текст, pdf, audio/video — `inline`, остальное отдаётся как `application/octet-stream` |
| `GET /api/search?path=&q=&mode=name\|content` | поиск по имени или содержимому, `regex=1`, `hidden=1`, `limit=` |
| `POST /api/batchrename` | `{"items":[{"from":"/a/1","to":"/a/2"},…]}`, одна операция Undo |
| `POST /api/touch` | `{"items":[…],"mtime":null}` (`null` = сейчас) |
| `POST /api/chmod` | `{"items":[…],"mode":"0755","recursive":false}` |
| `GET /api/archive/list?path=` | содержимое ZIP/TAR(.gz/.bz2/.xz) |
| `POST /api/archive/extract` | `{"archive":"/a.zip","dest":"/b","overwrite":false}` |
| `POST /api/archive/create` | `{"items":[…],"dest":"/b","name":"out.zip","format":"zip"}` |
| `GET /api/hash?path=&algo=sha256\|md5\|sha1` | контрольная сумма файла |
| `GET /api/properties?path=` | размер, даты, права, MIME, симлинк |
| `POST /api/delete` | добавить `"trash":true` — удалить в корзину вместо окончательного удаления |
| `GET /api/trash` | список корзины |
| `POST /api/trash/restore` / `/api/trash/purge` | `{"items":[id,…]}` — восстановить / удалить навсегда |
| `GET /api/undo/history` | метки последних операций Undo/Redo (без путей снимков) |
| `POST /api/redo` | повторить последнюю отменённую операцию |
| `GET /api/upload/status?uploadId=` | состояние докачки |
| `POST /api/upload/chunk?path=&uploadId=&offset=&total=&name=` | сырой кусок загрузки (1 МБ), `name` может содержать вложенный путь |
| `POST /api/upload/cancel?uploadId=` | отменить загрузку и удалить `.part` |
| `GET /api/audit?limit=200` | последние события аудита |

Корзина и незавершённые загрузки живут вне `root` (в `/tmp`), не видны
ни в панели, ни по FTP и не мешают лимитам API.

Ошибки — JSON `{"error":"…"}` с кодом: `400` неверный путь/запрос,
`403` нет прав или выход за корень, `404` нет файла, `409` уже существует,
`401` нет токена, `403` сервер в режиме только для чтения,
`413` слишком большой архив, `429` слишком много попыток входа.
Несовпадение `offset` при докачке тоже даёт `409`.

Статика отдаётся без кэша: `/`, `/index.html`, `/app.js`, `/config.js`.
`config.json`, `server.py`, `places.json` по HTTP **не отдаются** (404).

Токены живут в памяти процесса (7 дней, до 128 штук); после перезапуска
сервера нужно войти заново.

## Запуск через systemd

```bash
sudo mkdir -p /opt/nerevar-fm
sudo cp index.html app.js config.js config.json server.py /opt/nerevar-fm/
sudo chmod 600 /opt/nerevar-fm/config.json      # там пароль!

sudo cp nerevar-fm.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now nerevar-fm

systemctl status nerevar-fm
journalctl -u nerevar-fm -f
```

Логи в стиле nerevar-hub:

```
[server.py pid=1234] Nerevar FM запущен: http://0.0.0.0:8090
  страница   : /
  API        : /api/*
```

`nerevar-fm.service`).

## Безопасность

* Один основной пароль на веб и FTP, запросы без токена → 401, вход
  троттлится. Пароль хранится только в `config.json` (не в JS и не в логах).
  Необязательный `view_password` даёт доступ только для чтения: так можно
  дать «смотровый» пароль, не открывая изменение файлов.
* `read_only: true` (или `--read-only`) запрещает все изменяющие API/FTP
  операции; в панели появляется пометка о режиме, кнопки правки бездействуют.
* Токен живёт в памяти и обновляется при каждом запросе: неактивность
  дольше `session_ttl` секунд → надо войти заново.
* Все пути нормализуются и обязаны лежать внутри `root` — и в API, и в FTP.
  Снимки Undo, корзина и незавершённые загрузки лежат вне `root` и скрыты
  от листингов; распаковка архивов дополнительно проверяет `..` и симлинки.
* `config.json` не раздаётся по HTTP; держи его `chmod 600`.
* Загрузка пишется в `.part` и атомарно переименовывается; кусочная загрузка
  хранит часть в `/tmp` и удаляет её при отмене — битый файл под рабочим
  именем не появится.
* Журнал аудита (`GET /api/audit`, окно Help → Audit log) хранит действия,
  IP, путь и код ответа, но никогда не пароли.
* HTTP без TLS: снаружи — только через reverse-proxy (nginx/caddy) с HTTPS
  и, желательно, basic-auth поверх пароля панели.
* FTP без TLS — только локальная сеть / VPN. PASV-диапазон и лимит клиентов
  задаются в `config.json`.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| панель открылась, списка нет, «host unreachable» | `server.py` не запущен или порт закрыт файрволом |
| «Wrong password» | пароль из `config.json` / `--password`; при генерации смотри лог |
| после перезапуска сервера панель просит пароль снова | так и задумано: токены живут в памяти |
| FTP подключается, но список/файлы не идут | PASV-порты режет файрвол/NAT; работай в локальной сети или открой диапазон |
| `403 path escapes the root` | путь ведёт за `--root` (в том числе через симлинк) |
| `409 already exists` | перенос/копирование не перезаписывает; удали или переименуй цель |
| не открывается картинка в Viewer | сервер отдаёт только безопасные типы inline; скачай файл |
| `403 read-only mode` | включён `read_only` / `--read-only` или вход по `view_password` |
| загрузка встала и не продолжается | нажми Resume в очереди; часть файла хранится в `/tmp`, пока сервер не перезапустился |
| архив не распаковался | внутри попытка выйти за корень, симлинк или неподдерживаемый формат — проверь `/api/audit` |
| файл пропал после удаления | посмотри окно Trash / Undo history — его можно восстановить |
